# Round-trip: diagrama de clases → código → diagrama (E6)

**Ingeniería directa:** `docs/design/clases.puml` (con `Notificador` ya en *Reservas*, ADR-005) → código Python 3.10 en `src/reservas/` (`dominio.py`, `puertos.py`, `servicios.py`, `adaptadores.py`), generado con IA (Prompt IA 2) y revisado por el equipo.
**Ingeniería inversa:** `pyreverse -o puml -p reservas src/reservas` → `img/classes_reservas.puml` y `img/classes_reservas.png` (también `packages_reservas.png`).

Comparación hecha mirando `img/clases-reservas.png` frente a `img/classes_reservas.png`.

## Hallazgo adicional sobre el diseño
`Cita.crear(paciente, cupo)` recibe un `Paciente` y un `Cupo`, pero en el código la cita no guarda referencia a ninguno. Además `ServicioReservas.reservar_cita(paciente_id, cupo_id)` solo recibe el id y el diagrama no tiene cómo obtener el `Paciente` (por eso `reservar_cita` quedó con `NotImplementedError`). Si Renzo agregó `RepositorioPacientes.buscarPorId` en su PR, regenerar el código y este round-trip.
