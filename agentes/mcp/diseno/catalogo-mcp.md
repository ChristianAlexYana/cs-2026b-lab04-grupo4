## Dominio disponible

- `ServicioReservasDespues.__init__(self, validador=None, notificador=None, fabrica=None) -> None` crea `cupos_db` en memoria para cada instancia. Sus valores iniciales son `Medicina General: True` y `Cardiologia: False`. Cada booleano representa disponibilidad directa por especialidad. El mapa carece de fechas, horarios, centros y cantidades. Las políticas de cupos alternativos pertenecen al flujo de reserva. [Servicio de reservas](../../../src/reservas/despues/servicio.py) · [Políticas](../../../src/reservas/politicas.py)
- `ServicioReservasDespues` recibe y modifica una `Cita` definida en `antes/servicio.py`. Esa clase tiene `id`, `paciente_dni`, `celular`, `especialidad`, `estado` y `cupo_ocupado`. Carece de fecha de atención y de fecha de registro. El servicio carece de una base de citas o de un método para listarlas. `eventos` guarda textos de notificación sin fecha y con celular. La otra `Cita`, en `dominio.py`, tiene `fecha_registro` y carece de fecha de atención y de referencia al `Cupo`. `RepositorioCitas` solo declara búsqueda por ID y guardado. Los lotes fechados del Lab 09 son grabaciones sintéticas independientes del servicio. [Cita del flujo](../../../src/reservas/antes/servicio.py) · [Entidades](../../../src/reservas/dominio.py) · [Puertos](../../../src/reservas/puertos.py) · [Grabaciones](../../../prompts/datos-prueba/grabaciones/)
- El validador predeterminado es `DniAdapter(ReniecSDK())`. `DniAdapter.validar_dni(self, dni: str) -> bool` exige ocho dígitos ASCII. El SDK local simula una respuesta favorable para esa entrada. Las pruebas verifican, entre otros casos, el rechazo de letras, espacios y dígitos de ancho completo, así como la ocupación del cupo y la emisión del evento al reservar. [Adaptador](../../../src/reservas/adaptadores.py) · [SDK simulado](../../../src/reservas/externos.py) · [Prueba de DNI](../../../tests/test_issue_02.py) · [Pruebas de comportamiento](../../../tests/test_comportamiento.py)

## Firmas de las herramientas

```python
cupos_disponibles(especialidad: str) -> CupoDisponible
citas_del_dia(fecha: str) -> ConsultaCitasDelDia
validar_dni(dni: str) -> bool
reservar_cita_borrador(dni: str, especialidad: str, celular: str) -> str
```

`CupoDisponible` y `ConsultaCitasDelDia` son tipos de salida estructurada de MCP. El kit ilustra el uso de `TypedDict` para publicar un `outputSchema` y devolver `structuredContent`. `reservar_cita_borrador` devuelve solo el nombre del Markdown como texto. [Servidor AgroConecta](../../../../lab11-kit/Lab11_recursos_MCP/servidor_mcp/agroconecta_mcp.py)

E2 conserva las cuatro firmas. El servidor devuelve un error MCP con el formato sintético admitido para corregir entradas inválidas de DNI. La firma Python sigue devolviendo `bool` y el SDK lo publica como `{"result": true}` o `{"result": false}`. El recurso `agents-md` usa la ficha MCP local en ausencia del archivo raíz. [Verificación del servidor](verificacion-servidor.md)

## Aprobación y datos

Las tres herramientas de consulta operan sin escritura. Antes de enviar la llamada de escritura, el cliente/host muestra la operación con los identificadores enmascarados y solicita aprobación explícita para esa llamada. Si falta aprobación, bloquea la llamada. La política del Lab 10 aporta el precedente de revisión humana y el kit muestra su aplicación a herramientas MCP. [Política del Lab 10](../../agente/politica.py) · [Política del kit](../../../../lab11-kit/Lab11_recursos_MCP/agente/politica.py)

- No consume cupos porque el borrador se crea sin invocar `ServicioReservasDespues.reservar_cita` ni escribir en `cupos_db`.
- No envía mensajes porque la creación del Markdown prescinde de eventos de reserva y del notificador de WhatsApp.
- No cambia datos existentes porque usa creación exclusiva de un nuevo `BORRADOR-NN.md` y deja intactos los archivos y las citas preexistentes.

El cliente usa solo datos de prueba sintéticos y enmascara DNI y celular en vistas de aprobación, borradores y trazas. Las respuestas excluyen nombres, identificadores personales completos y textos de `eventos`. Los formatos de prueba siguen las convenciones del repositorio.
